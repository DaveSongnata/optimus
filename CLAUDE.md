# Optimus — Steering Document

Optimus is a CorelDRAW add-in + companion desktop app that **optimizes `.cdr` files**, audits
**colors/fonts/accents**, and performs **Windows maintenance**. Sibling project to SisCut
(`../siscut/`) and AiSten (`../ai-sten/`); it deliberately reuses their proven plugin/installer
architecture but is **much leaner**: no license gate, no Rust engine, no SQLite, no external service.

Plan: `plans/index.md` + `plans/Phase_1..8.md`.

---

## Architecture Golden Rule
- **Pure logic (algorithms, rules, parsing, math) → `netstandard2.0`** — testable on .NET 8, no COM.
- **I/O with CorelDRAW / Windows → `net48`** — the only place `dynamic` COM and Win32 live.
- **Tests → `net8.0` + xUnit.** Every algorithm ships with tests written FIRST.
- The COM/Win32 shells are deliberately dumb: no business logic, no algorithms.

## CorelDRAW COM Rules
- **Escrita de cor só em forma-FOLHA** (O24). Preencher um grupo repinta todos os filhos, e `cdrColorMixed` não é cor.
- **Conferir o membro no dump inclui conferir a INTERFACE dele** (O22). `ApplyUniformFill` existe — em `IVGFill`, não em `IVGShape`.
- **Toda passada COM em massa tem contador de falha e guarda a primeira exceção** (O22). `catch { }` mudo faz falha parecer "nada a fazer".
- **NEVER guess a VGCore constant or member.** The authoritative source is the typelib dump at
  `docs/vgcore-tlb-dump.txt` (VGCore 25.2, 8454 lines, generated by `docs/dumptlb.ps1`). Grep it
  first; if a member is absent there, treat it as nonexistent until proven on the VM.
- **`cdrMillimeter = 3`. `4` is `cdrCentimeter`** — the historic 10× bug that broke SisCut and was
  re-introduced in Optimus v1.0. Verified in the dump (`ENUM cdrUnit`).
- Late-bound (`dynamic`) COM behind an interface → one binary for CorelDRAW 2024/25/26.
- COM is **in-process and cheap** inside the add-in (out-of-process marshalling is ~1 ms/property
  and is what made SisCut's tester look slow — that is a tester artifact, not the plugin).
- **`Shape.PowerClip.Shapes` must be traversed explicitly** — `Page.FindShapes(Recursive:=True)`
  is not expected to descend into PowerClips. Design files are full of them; missing this makes an
  optimizer silently do nothing (proven: Optimus v1.0 achieved 0% on real client files).
- Prefer the verified `Page.FindShapes(Name?, cdrShapeType?, Recursive?)` over hand-rolled recursion.
- **`Fill.UniformColor` is a LIVE reference into the document.** `ConvertToRGB()`/`ConvertToCMYK()`
  mutate in place. Always `Color.GetCopy()` before inspecting — reading colors must never alter art.
- **A late-bound call that OMITS a trailing optional parameter can fail** with "Could not convert
  argument 0". Measured on Corel 2024: `document.SaveAsCopy(path)` — whose signature is
  `SaveAsCopy(String FileName, StructSaveAsOptions Options?)` — aborted every optimization run. The C#
  `dynamic` binder cannot satisfy that dispatch signature. Fix: pass every parameter, or invoke through
  `InvokeMember` (no optional-parameter metadata). Better still, avoid the COM call — the backup is now
  a plain `File.Copy`, which is byte-identical to what the operator has (`SaveAsCopy` re-serialises).
- Pair `Document.BeginCommandGroup` / `EndCommandGroup`; an unpaired Begin corrupts undo.
- Always restore document state (unit, view) on error.
- Verified constants in use: `cdrCurveShape=3`, `cdrBitmapShape=5`, `cdrTextShape=6`, `cdrGroupShape=7`,
  `cdrOLEObjectShape=12`, `cdrEPSShape=27`; `cdrUniformFill=1`, `cdrFountainFill=2`, `cdrTextureFill=8`,
  `cdrPatternFill=9`, `cdrHatchFill=10`; `cdrColorCMYK=2`, `cdrColorRGB=5`, `cdrColorSpot=25`;
  `cdrNoThumbnail=0`; `cdrTextPropertyFont=4`.

## Product Philosophy — the product is a REMAP, not a magic button (Davi 2026-07-25)
- **Everything is ADJUSTABLE.** The operator chooses the trade-off; the product never decides for them.
- **No jargon in the UI.** "ICC" → **FIDELIDADE DE COR**; "DPI" → **QUALIDADE DE IMAGEM** with
  destinations (impressão fina / grande formato / tela). A CorelDRAW operator is not a technologist.
- Every control is a slider with both ends LABELLED by consequence:
  *maior economia / cores menos fiéis* ↔ *menor economia / cores mais fiéis*.
- **Estimate BEFORE applying**, real measurement after. Never only after.
- **A lever the file does not have appears DISABLED with the reason** — never promising savings that
  cannot happen (e.g. `kaneki.cdr` has no embedded ICC, so the colour slider must say so).
- Loss is stated in the LABEL, not in a footnote.
- **The interface is as important as the technique** — a file the operator cannot reason about is a
  file they will not trust.

## UI Rules
- **WebView2 + HTML, 100% offline.** Never a CDN, never a webfont — the client must work with no
  internet. Assets are embedded in the DLL and served via `SetVirtualHostNameToFolderMapping`.
- **JS→C#: read with `e.WebMessageAsJson`**, never `TryGetWebMessageAsString()` (the page posts
  objects; the string API throws "Value does not fall within the expected range" — the v1.0 bug).
- **C#→JS: `ExecuteScriptAsync("window.optimusReceive(...)")`** — the `message` event channel is
  unreliable inside CorelDRAW's WPF docker host (foreign Dispatcher race).
- Register `AssemblyResolve` from the addon folder — the CorelDRAW host does not add it to the
  probe path.
- **The HTML holds NO user-facing text.** Every string is a key (`data-i18n` / `T('key')`) served from
  `Optimus.Core/I18n`. The catalog is injected with `AddScriptToExecuteOnDocumentCreatedAsync` so it
  exists *before* the page script; delivering it by message shows a flash of empty labels. Switching
  language must `RemoveScriptToExecuteOnDocumentCreated` first — injections accumulate and two catalogs
  leave the page bilingual. Pass the language to `toLocaleString` too, or `14.342` reads as a decimal.
- **Never test translation completeness by comparing text** — pt and es legitimately share "Copiar",
  "Moderado", "Objetos", "Resultado". Assert on explicit key presence (`LocalizedStrings.HasExplicit`).
- **Nothing may ever take CorelDRAW down.** Every handler is wrapped; failures degrade to a log
  line in `%TEMP%\Optimus\docker.log`.
- **Status = forma + símbolo + texto; cor é reforço** (O20). Nunca sinalizar severidade só por cor.
- **Nenhum valor visual escrito à mão** — tamanho, raio, espaço e sombra saem dos tokens (O21).
- Brand palette: action `#C2410C` (branco por cima = 5,18:1), fill-only `#EA580C` / `#C2410C`, ink `#1C1917`, paper `#FBFAF8`.

## Windows Maintenance Rules (evidence-based — see `plans/Phase_6.md`)
- **No placebo.** RAM "cleaning" (`EmptyWorkingSet`, standby-list purge) makes the machine slower
  and is NOT shipped. Clearing Prefetch is negative-value and is NOT shipped. Same bar rejects the
  other three staples of "PC booster" software: **disabling Windows services** (breaks printing,
  updates and licensing weeks later), **pagefile surgery**, and **process-priority boosting**.
- **The module is an OPTIMIZER, not a cleaner** (Davi 2026-07-25, on seeing v1.9.0). Deleting files is
  one tab; the first tab is **Desempenho** — the things Windows trades away for looks or battery and a
  print shop pays for nothing: power plan, interface animations, transparency, menu delay, antivirus
  and search-index scanning of the artwork folders. Every one reads its CURRENT state, is applied only
  when asked, states what is given up, and is **reversible from the same screen** (previous value
  stored under `HKCU\SOFTWARE\Aisten\Optimus\PerfBackup`).
- **Never apply Windows' own "best performance" preset.** It also kills ClearType and thumbnails —
  for a designer that is damage, not optimisation. Optimus writes `UserPreferencesMask` by hand,
  clearing the animation bits while keeping font smoothing and drag-full-windows ON.
- Running elevated makes `%TEMP%`/`%LOCALAPPDATA%` resolve to the **admin's** profile. Enumerate
  real profiles via `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList\<SID>\ProfileImagePath`.
  Getting this wrong is the #1 reason cleaners "free nothing" (the v1.0 bug).
- **Age-gate temp deletion (≥72 h).** Deleting a temp file an open app still holds corrupts documents.
- The headline number is the **disk's real free-space delta**; per-category figures are labelled
  estimates and their sum is never presented as the result.
- `cleanmgr`'s `DownloadsFolder` handler **deletes the user's Downloads** — must be explicitly
  zeroed in `VolumeCaches`, never merely "not enabled".
- Restore-point creation **returns success while doing nothing** if one exists from the last 24 h;
  verify by sequence number, and never assume System Restore is even enabled.
- Media-aware only: `defrag /O`, never `/D` on an SSD. Detect via `MSFT_PhysicalDisk.MediaType`
  (3=HDD, 4=SSD). SMART must layer on `MSFT_PhysicalDisk.HealthStatus` —
  `MSStorageDriver_FailurePredictStatus` returns "not supported" on NVMe.
- **Startup audit has FIVE surfaces, and the fifth is not optional.** Run HKCU + Run HKLM +
  `Wow6432Node` + Startup folders + **Task Scheduler logon/boot triggers**. Measured on a real
  machine: 11 items in the four classic surfaces, **4 more only in Task Scheduler** (MSI Afterburner,
  Edge updater, a driver's audio task) — modern updaters moved there precisely because users clean the
  Run keys. Bind the scheduler late via `Schedule.Service` (no interop assembly to ship).
- **Disable, never delete**, and via Windows' own encoding: `StartupApproved\Run` (first byte `0x02`
  enabled / `0x03` disabled) for the registry+folder surfaces, `Task.Enabled = false` for scheduler
  ones. Both stay reversible from the Windows UI. Read the same keys back, or the tool "optimises" the
  same three items forever.
- **Protect essentials by broad substring, deliberately over-inclusive.** A real driver task was named
  `iGoAudioTaskSession` and matched neither `realtek` nor `rtkaudio`. Over-protecting costs a missed
  optimisation; under-protecting costs a shop machine with no sound or no tablet.
- Anything that needs a service (`wuauserv`, `Spooler`) or Explorer stopped restores it from a
  `finally`, remembers whether it was running first, and retries. A shop left with a dead spooler or no
  taskbar is a worse outcome than not cleaning at all.

## Licensing / Third-party Rules
- **Bundle only permissive licenses** (MIT/Apache-2.0/BSD/zlib/public-domain) in this
  closed-source commercial product. Ship `THIRD-PARTY-NOTICES.txt`.
- **Never bundle:** BleachBit (GPLv3), any Sysinternals binary (EULA forbids redistribution),
  Pantone color data (documented DMCA enforcement — echo the name from the customer's own file
  via `Color.SpotColorName` / `Palette.MatchColor` instead of shipping a table).
- Winapp2.ini is CC BY-SA 4.0: shippable verbatim with attribution, but any adaptation makes the
  **rule file** ShareAlike. Decision: write our own rules (file locations are facts, not copyrightable).
- Prefer in-box Windows facilities (cleanmgr, DISM, WMI, Restart Manager, `defrag /O`) over any
  third-party dependency.

| O19 | **To LIST the colours, never walk the shapes.** `ColorCollector` reads ~25 late-bound properties per shape — ~420.000 COM calls and **90 s** on a 16.899-shape file (measured). `Document.AddColorsToDocPalette()` + `Document.Palette` makes CorelDRAW do the same scan in its OWN native code and hands back the finished list: the loop becomes one over COLOURS (~128) instead of one over SHAPES (~16.899), so it costs seconds. | O15 | **THE lever on a repeated-art file is REPETITION, and node simplification DESTROYS it.** Measured on `kaneki_no_ponto.cdr`: 16.914 objects store only **4.789 distinct coordinate blocks** — 71,4% of shapes are byte-identical copies placed by different transforms. Storing each once saves **4.628.466 bytes = 58,2% of the file, LOSSLESS**. Deflate cannot see it: its window is 32 KB and `data1.dat` is 28 MB, so the copies sit megabytes apart (the opposite of the style JSON in O8, whose repetition is local and free). **Our own AutoReduce run raised distinct blocks from 4.789 to 5.400 and cut the recoverable share from 58,2% to 23,7%** — simplifying each shape independently makes identical copies stop being identical. ORDER IS NOT NEGOTIABLE: detect repetition → instance/symbol → only then simplify. Never the reverse |
| O12 | **Bulk edits MUST run inside `Application.Optimization = true` + `EventsEnabled = false`.** Without it CorelDRAW repaints and fires events after every single edit: simplifying 14.342 curves took **13 min 22 s** on a real file. Restore both from a `finally` and force one final `Refresh()` — a session left with `Optimization = true` stops repainting and looks frozen |
| O13 | **`Window.Refresh()` cannot be timed — it only POSTS a repaint and returns.** Measured 0,1 ms before and 0 ms after removing 130.000 nodes. Any "more fluid" built on it is noise dressed as evidence. Time a **synchronous render** instead (`Document.ExportBitmap` + `ExportFilter.Finish()`), and call it "tempo para desenhar", not "redraw" |
| O14 | **Removing N% of the nodes does NOT shrink the file by N%.** Measured on `kaneki.cdr`: nodes −31% produced bytes −14,3% against a 24,8% estimate. The container is a ZIP — coordinates deflate, and simplified coordinates compress slightly worse per byte. The estimator carries a `DeflateRecovery` factor (0,55, deliberately under the 0,63 measured) because over-promising is a lie and under-promising is only a disappointment (P1) |
| O11 | **A `.cdr` component's LOGICAL size is not its cost — weigh it COMPRESSED, on disk.** The container is a ZIP. `kaneki.cdr`'s suspected orphan `Bitmaps.dat` is 477 KB logical but **85 KB stored = 1,07% of the file**, so it was never a lever; and it is not orphaned either (`kaneki_no_ponto.cdr`, the same art minus the frames, has no `Bitmaps.dat` at all). Quoting logical bytes would have promised ~6% and delivered 1%. Same trap as the style JSON in O8 |
| O10 | **Where .cdr size actually lives (measured on 44 real files).** X6+ is a ZIP; the biggest items are ZIP ENTRIES, not RIFF chunks: `color/profiles/**` (ICC — up to **97.3%** of a file), `embed/embedding*` (fonts — up to **93%**), `content/data/Bitmaps.dat` (raster, stored UNCOMPRESSED), `previews/*.png` (STORED, incompressible). Node coordinates are ~4% on disk. **Never scan document streams for an ICC signature — it is a false negative.** And **removing ICC is NOT free**: `color/color.xml` shows the profile is referenced in 29/29 real files, so it is a colour-management trade-off requiring consent (P3) |
| O9 | **COM cost is per OBJECT TOUCHED, not per call** — measured: 110 s of a 174 s walk was RCW cleanup (STA `Release` runs on the owning thread and blocks it). Always `Marshal.ReleaseComObject` shapes, `Curve`, `Nodes` and ranges explicitly. And **`FindShapes` with a TYPE FILTER is not a source of truth**: summing it over all 27 enum values gave 6.118 shapes where the unfiltered call gave 16.899 on the same page. Enumerate `FindShapes(,, true)` ONCE and read each `.Type` |
| O8 | **Size and fluidity are two different objectives — and how much each lever is worth is PER FILE, never a constant** (Davi 2026-07-24, revised 2026-07-25 after measuring). Always measure the file before quoting a lever. Measured extremes: on an ICC-dominated file the profile is **97.3%** and geometry is a rounding error; on a geometry-dominated drawing (`kaneki.cdr`) geometry is **97.3% of the object payload ≈ 73% of the file**, so halving the nodes is worth tens of percent — NOT the ~2% an earlier single-file measurement suggested. **The duplicated per-object style JSON is a non-lever**: 12.0 MB logical (more than the geometry) deflates to 125 KB = 2.1%, because it is a few distinct strings repeated thousands of times. And never sell fluidity without **measuring redraw time** (`ActiveView.ToFitPage()` + timed `Window.Refresh()`) |
